## 0. สิ่งที่เจอสำคัญ (สรุป)

1. **สคีมา v3 มีตาราง `orders`, `prices` (มี `date`), `shops` อยู่แล้ว** และมีการตรวจ reference ครบ (ร้าน/ยา/ยาสามัญ) — แต่ยังไม่มีโค้ดไหนเขียนลงตาราง `orders` (ข้อมูลจริงจึงเป็น `[]`) ดังนั้น**แก้รูปแบบ order line ได้ปลอดภัย** ไม่ชนข้อมูลเดิม
2. **จุดที่สคีมาปัจจุบันรับไม่ได้ 3 จุด**: (ก) ยาเดียวกันหลายคน — `source.assignmentId` เป็นคนเดียว แต่ใบสั่งรวมเป็นบรรทัดเดียว ต้องรู้ว่าของที่รับแบ่งเข้าสต็อกใครเท่าไร (ข) ค่าส่งไม่ถูกเก็บเป็นตัวเลขตอนสั่ง (เก็บแค่ `includeShipping`) ถ้าแก้ร้านทีหลัง ยอดในประวัติจะเปลี่ยน (ค) ไม่มีวันที่รับ/ยกเลิก
3. **v2 ใช้ซ้ำไม่ได้ตรง ๆ** (ผูกกับ v2 `Root`) และ **กฎเทียบร้านเปลี่ยน**: v2 ตัดร้านที่ขาดราคาแม้รายการเดียว สเปกใหม่ให้นับเฉพาะรายการที่มีราคา + "ไม่รวม N รายการที่ยังไม่มีราคา" — ต้องเขียนใหม่และเขียนเทสต์ใหม่

5. **ราคาต่อ "ร้าน×ยา×หน่วยขาย"**: สคีมาไม่ห้ามมีหลายแถวต่อร้านต่อยา จึงเก็บหลายหน่วยขายได้โดยไม่แก้สคีมา — ต้องเป็นกฎใน domain (upsert ด้วยคีย์ shop+item+sellUnit) แต่ **ยาใหม่พิมพ์เอง (free) ไม่มีที่เก็บราคาจำ** (ราคาผูกกับ medication/houseItem) → ดูคำถาม Q-B

## 3. กติกาหน่วย: ในใบสั่ง และตอนรับของ → อัปเดตสต็อก

หลักใหญ่: ใบสั่งนับเป็น **หน่วยขาย** (`qty` ของ `sellUnit`) → หน่วยยา = `qty × perSellUnit`. รับของแล้วใช้ `refillStock` ของ v3 (`stock.ts`) ซึ่ง "เติมบนของที่เหลือ ณ เช้าวันนี้ และตั้ง `countedOn`=วันนี้", ไม่สร้าง MedEvent, รวมวันหมดอายุไม่เกี่ยว (ไม่มีวันหมดอายุตอนสั่ง → ไม่ส่ง)

| ชนิด | หน่วยสั่งที่เห็น | `perSellUnit` | รับของ → สต็อก (`stock`) | หมายเหตุ |
|---|---|---|---|---|
| ยาเม็ด/แคปซูล — แผง (`pack: strip/box`) | แผง หรือ กล่อง | เม็ดต่อแผง (`perStrip`) หรือ ต่อกล่อง (`strips × perStrip`) | `count`: เพิ่ม `loose` = `qty × perSellUnit` (เม็ด) — `refillStock` จะรวมแล้วแปลงกลับเป็น `strips + loose` เอง | ถ้าหน่วยขาย "กล่อง" ต้องรู้เม็ดต่อกล่อง ใส่เองได้; ค่าเริ่มต้นจาก pack |
| ยาเม็ด/แคปซูล — ขวด/กระปุก (`pack: bottle`) | ขวด | `perBottle` | `count`: เหมือนข้างบน ("strip" = 1 ขวดเต็ม) | `packWord` = "ขวด" |
| ยาเม็ดไม่มี pack (`none`) | เม็ด (หรือหน่วยอื่นที่เจ้าของพิมพ์) | จำเป็นถ้าหน่วยไม่ใช่เม็ด | `count`: `strips:0, loose` = เม็ดที่รับ | `unitsPerStrip` = null → ห้ามเติมเป็น "แผง" (`refillStock` ปฏิเสธเอง) |
| ซอง (`sachet`, `sachetBox`) | กล่อง หรือ ซอง | ซองต่อกล่อง (`sachets`) | `count`: เพิ่ม `loose` = จำนวนซอง | "strip" ของซอง = 1 กล่อง |
| ยาน้ำ (`liquid`, `container ml`) | ขวด | มล. ต่อขวด (`pack.amount`) | `volume`: `ml += qty × perSellUnit` | ใช้ `RefillAmount.volume` |
| ครีม (`cream`, `container g`) | หลอด | 1 (นับเป็นหลอด) | `tubes`: `spare += qty` | **ไม่หักอัตโนมัติ** ตามกติกาเดิม; ไม่ใช้ `perSellUnit` |
| ยาหยอด (`drops`, `container`) | ขวด (หรือหลอด ตามที่เจ้าของเรียก) | 1 | `tubes`: `spare += qty` | `RefillAmount.tubes` ต้องเป็นจำนวนเต็ม > 0 |
| ยาอื่น ๆ (`other`) | หน่วยที่พิมพ์ | — | ไม่มีกฎสต็อกตายตัว (`stockProblem` ยอมทุกแบบ) → **ไม่อัปเดตสต็อกอัตโนมัติ** เว้นแต่มี `stock` อยู่แล้วเป็นชนิดไหนก็เติมชนิดนั้น | Q-G |
| ยาสามัญ (`houseItems`) | หน่วยเดียวกับ `stock.unit` | 1 | `stock.qty += qty` ถ้ามี `stock`; **ไม่มี `stock` (ไม่นับ) = ไม่อัปเดต** | หน่วยขายของราคา ≠ `stock.unit` ได้ไหม → Q-H |
| ยาใหม่พิมพ์เอง (`free`) | หน่วยที่พิมพ์ | ไม่บังคับ | **ไม่อัปเดตสต็อกเลย** (ยังไม่มียาในระบบ) แล้วถาม "เพิ่มเข้ารายการยาไหม" | เก็บ `addToList` |

**ยาเดียวกันหลายคน (สต็อกแยก)**
- ใบสั่ง: 1 บรรทัดต่อยา (ราคา/หน่วยขายร่วม), จำนวนสั่ง = ผลรวมความต้องการของทุกคนที่กินยานี้ (เหมือน v2 Q6)
- `shares` เก็บความต้องการเป็น **หน่วยยา** ต่อ assignment ตอนสร้างใบ (คนที่สต็อกพอแล้ว `need = 0` ก็ไม่มี share)
- รับของ: จำนวนหน่วยยาที่รับ = `qtyReceived × perSellUnit` แบ่งตามสัดส่วน `shares` (ปัดเป็นเม็ดเต็ม ส่วนที่เหลือจากเศษให้คนที่ขาดมากสุด; ไม่เกินจำนวนที่รับ) แล้วเรียก `refillStock` ทีละ assignment
- ยาหลอด (tubes) แบ่งเป็นจำนวนเต็มหลอด: แจกตามลำดับความต้องการ ถ้าน้อยกว่าจำนวนคน คนที่เหลือไม่ได้ → **ต้องให้เจ้าของยืนยันกฎนี้ (Q-F)**
- สมาชิกที่ถูกนำออกหรือหยุดยาหลังสั่ง: ข้าม share นั้น (ไม่เติมสต็อก assignment ที่ `stopped`) และแจ้งในแผ่นรับของ
- Assignment ที่ `stock = null` (ไม่เคยนับ): `refillStock` เริ่มนับจากของที่รับ → **ต่ำกว่าจริงถ้าที่บ้านมีเหลือ**; ต้องมีข้อความเตือนในแผ่นรับของ (Q-I)

**กติกายาหลอด (ข้อเสนอ รอเจ้าของยืนยัน — ตามที่สั่ง)**: ในใบสั่งนับเป็น "หลอด/ขวด"; รับของแล้ว `spare += qty`; ไม่คำนวณวันเหลือ; ไม่เปิดหลอดอัตโนมัติ (ผู้ใช้กด "เปิดหลอดใหม่" เอง = `openNewTube` เดิม); ติ๊กอัตโนมัติ "ใกล้หมด" เมื่อ `tubeLevel` = `low` หรือ `out` — **ต้องยืนยัน** เพราะ `isLowStock` ปัจจุบันถือว่า tubes "ไม่ใกล้หมดเสมอ" (Q-J)

## 5. ความเสี่ยง

1. **ข้อมูล v3 เดิมเข้ากันได้ไหม** — ได้ เพราะ `orders` ในข้อมูลจริงเป็น `[]` (ไม่มีโค้ดไหนเขียน) การเปลี่ยนรูป `source` จึงไม่ต้อง migrate และ `version` ยังเป็น 3. ความเสี่ยงอยู่ที่ **fixtures/เทสต์ใน repo** (มี order ตัวอย่าง 4 ใบรูปเก่า) ต้องแก้พร้อมกัน; ถ้าเจ้าของเคยส่งไฟล์สำรองที่สร้างจาก fixture ตัวอย่าง (`isSample`) จะอ่านไม่ผ่านหลังแก้ → ตรวจ `isSample` และให้ข้อความ `invalid` ที่ชัด (ต้องถามเจ้าของ Q-K ว่ามีไฟล์สำรองตัวอย่างค้างอยู่ไหม)
2. **ห้ามแตะ localStorage key นอก `judya.v3` / `judya.v3.prev`** — ราคาจำ, ร่างใบ, ประวัติ ทั้งหมดต้องอยู่ใน `Root` เท่านั้น; ห้ามเก็บร่างใบ/การตั้งค่าหน้าสั่งยาใน key ใหม่ (ร่างค้างข้ามรีโหลด = ต้องเพิ่มลง `Root` ซึ่งเป็นการเปลี่ยนสคีมา → Q-E). ทุกจุดเขียนต้องผ่าน `saveRoot` (มี safety copy `.prev` และจับ quota แล้ว)
3. **`check:overflow` ที่ 360px ทุกขนาดอักษร** — หน้าสั่งยาหนาแน่นที่สุด (ชื่อยา+หน่วยสั่ง+ช่องตัวเลข 2 ช่อง+ปุ่ม +/−+ราคา ในแถวเดียว): ต้องออกแบบเป็นการ์ดหลายบรรทัด ไม่ใช่ตาราง; ชื่อยา/ชื่อร้านยาวต้องตัดบรรทัด; ช่องตัวเลข ≥ 44px; ต้องเพิ่ม URL ของทุกสถานะใน `scripts/check-overflow.mjs` (ว่าง, ปกติ, ชื่อยาวมาก, ใบ 4 สถานะ, แผ่นทุกใบ) ที่ 360/412px × 3 ขนาด
4. **ขนาด bundle** — ยังไม่ได้วัด (ไม่ได้ติดตั้ง dependency ในรอบอ่านอย่างเดียวนี้). ความเสี่ยงต่ำ: ไม่มี dependency ใหม่ ใช้ `zod` เดิม. ให้วัด `npm run build` ก่อน/หลังแต่ละขั้น และรายงานขนาด JS (gzip) ใน PR; ถ้าเพิ่ม > ~30 KB gzip ให้แยกหน้าสั่งยาเป็น lazy chunk
5. **ขนาดข้อมูล** — ใบสั่งไม่มีเพดาน; `localStorage` ~5 MB (ไฟล์สำรองเพดาน 5 MB เหมือนกัน): ใบละ ~1–2 KB ถือว่าไกลเพดานมาก แต่ต้องมีเทสต์ quota เดิม (บันทึกล้มเหลว → ข้อมูลเดิมไม่หาย)
6. **ความถูกต้องของตัวเลขยา** — การแบ่ง `shares`, การรับรอบสอง (ส่วนต่าง), และ `refillStock` ที่ตั้ง `countedOn`=วันนี้ ต้องไม่ทำให้ "วันเหลือ" ของคนอื่นเพี้ยน: เทสต์ต้องเทียบ `daysLeft` ก่อน/หลังรับ
7. **ลบร้านที่มีใบอ้างอยู่** — `deleteShop` (ถ้าจะมีในหน้านี้/PR 14) ทำให้ reference check ล้มตอนกู้คืน — ต้องกำหนดกฎก่อนเปิดปุ่มลบ (Q-C)
8. **ชื่อซ้ำ** — "ยาใหม่พิมพ์เอง" ที่ชื่อเหมือนยาในระบบ (ไม่สนตัวพิมพ์/ช่องว่าง) ต้องชี้ให้เลือกยาในระบบ ไม่งั้นรับของแล้วไม่อัปเดตสต็อกโดยที่เจ้าของไม่รู้

## 6. คำถามถึงเจ้าของ (ห้ามเดา — ก่อนเริ่ม 11.1)

- **Q-A** ใบสั่งกี่ร้านต่อกัน: เทียบ 3 ร้านแล้ว **เลือก 1 ร้าน = 1 ใบ** ใช่ไหม? (สคีมาตอนนี้ 1 ใบ = 1 ร้าน) หรืออยากสั่งแบ่งหลายร้านใน "ใบเดียว"?
- **Q-B** ยาใหม่พิมพ์เอง (ยังไม่อยู่ในรายการยา): ให้ **จำราคาไว้ตามชื่อ** (ต้องเพิ่มที่เก็บราคาตามชื่อ = เปลี่ยนสคีมา `prices`) หรือจำเฉพาะยาที่อยู่ในระบบ (ยาพิมพ์เอง ต้องพิมพ์ราคาใหม่ทุกครั้ง จนกว่าจะถูกเพิ่มเข้ารายการยา)?
- **Q-C** ลบร้านที่มีใบสั่งอ้างอยู่: (ก) ห้ามลบ (ข) ลบได้แต่เก็บชื่อร้านไว้ในใบ (ต้องเพิ่ม `shopName` ในใบ) (ค) ลบร้านพร้อมลบใบ — แนะนำ (ข)
- **Q-D** ยกเลิกใบที่ **รับบางส่วนไปแล้ว**: สต็อกที่เพิ่มไปแล้วคงไว้ (แนะนำ) หรือหักคืน?
- **Q-E** ร่างใบสั่ง (ที่ติ๊ก/แก้จำนวนไว้แต่ยังไม่กด "สั่งแล้ว"): หายเมื่อปิดหน้า (แนะนำ, ไม่เปลี่ยนสคีมา) หรือค้างข้ามการรีโหลด (ต้องเพิ่มลง `Root`)?
- **Q-F** ยาเดียวกันหลายคนตอนรับของ: แบ่งตามสัดส่วนที่สั่งไว้ตอนแรก (แนะนำ) หรือให้เจ้าของเลือกเองว่าเข้าสต็อกใครเท่าไร? และยาหลอด/ขวดหยอดที่น้อยกว่าจำนวนคน ให้ใคร?
- **Q-G** ยาชนิด "อื่น ๆ" (`other`): รับของแล้วไม่อัปเดตสต็อกอัตโนมัติ ตกลงไหม?
- **Q-H** ยาสามัญ: หน่วยที่สั่งกับหน่วยที่นับสต็อกต่างกันได้ไหม (เช่น สั่งเป็น "ขวด" แต่สต็อกนับ "มล.") — แนะนำให้ล็อกให้เป็นหน่วยเดียวกัน; และยาสามัญที่ **ไม่นับสต็อก** รับของแล้วถามให้เริ่มนับไหม?
- **Q-I** ยาที่ยัง **ไม่เคยนับสต็อก** รับของแล้วเริ่มนับจากของที่รับ ตกลงไหม (ข้อความเตือนว่าไม่รวมของที่มีอยู่ก่อน) หรือให้ถามจำนวนที่มีอยู่เดิมก่อน?
- **Q-J** ยาหลอด (ครีม/ยาหยอด): ติ๊กอัตโนมัติ "ใกล้หมด" เมื่อ **ไม่มีหลอดสำรองและเปิดใช้อยู่ (low) หรือไม่มีเลย (out)** ใช่ไหม? (ตอนนี้ `isLowStock` ไม่นับ tubes เลย) และยืนยันกติกา "นับเป็นหลอด/ขวด → รับแล้วเพิ่มเป็นหลอดสำรอง"
- **Q-K** มีไฟล์สำรอง/ข้อมูลตัวอย่าง (`isSample`) ที่สร้างไว้แล้วและมีใบสั่งตัวอย่างอยู่ในเครื่องหรือไม่? (ถ้ามี รูปใบสั่งใหม่จะอ่านไม่ผ่าน — ต้องล้างหรือกู้ใหม่)
- **Q-L** ปุ่ม "สั่งยา" บนการ์ดยาใกล้หมด (Home) ใน PR นี้ผูกแล้ว (11.6) แต่ปุ่มในหน้ารายการยา/สมาชิก แยก PR ทีหลัง ตกลงไหม? และไทล์ "สั่งซื้อยา" บน Home ผูกด้วยใช่ไหม (ถือว่าใช่)
- **Q-M** ใบสั่งเก่ามากน้อยแค่ไหนเก็บ: ไม่มีเพดาน (ตาม Q13 เดิม) ตกลงไหม หรือล้างใบที่รับ/ยกเลิกแล้วเกิน N เดือน?
