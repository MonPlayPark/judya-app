## 1. สรุป 10 บรรทัด

1. โค้ด M3 ครอบคลุม "แกนยา" ได้ดี: ยา 1 ชื่อใช้ร่วมหลายคน, ตารางกินยา, คำนวณสต๊อกทีละวัน, ราคาต่อร้าน, เทียบร้านและข้อความ LINE, สำรอง/กู้คืน, ล็อกซูม — **ประมาณ 35–40% ของสเปก M4 มีแล้วหรือแก้เล็กน้อย**
2. ที่ยัง**ไม่มีเลย**: ชนิดยา, หน่วยบรรจุ/ความแรงแบบมีโครง, ยาครีม/ยาหยอดนับหลอด, แพ้ยา, ผลข้างเคียง, สิทธิ์รักษา, ใบสั่งยาที่เก็บถาวร (สถานะ/ประวัติ/รับของ/สั่งซ้ำ), ใบเสร็จแนบรูป, หน้าตั้งค่าย่อย 5 หมวด
3. **เรื่องสคีมาใหญ่สุด 5 เรื่อง:** (ก) `Medication` ได้ชนิด+บรรจุภัณฑ์+ความแรงแบบมีโครง และสต๊อกเป็น "แผง + เม็ดเดี่ยว / มล. / หลอด" (ข) ตาราง `orders` ใหม่ทั้งชุด (รายการ สถานะ รับของบางส่วน) (ค) `Person` เพิ่มแพ้ยา 3 สถานะ + สิทธิ์รักษา + อวาตาร์ที่เลือกได้ + ตัดวันเกิดเหลือปี (ง) `MedEvent` เหลือ 4 ชนิดฝั่งหมอสั่ง และตัด `edit` ทิ้ง (จ) `Price` เพิ่มวันที่ + รูปใบเสร็จ
4. **ความเสี่ยงที่ 1: รูปใบเสร็จ** — เก็บใน `localStorage` ไม่ได้ (เพดาน ~5 MB และไฟล์สำรองจำกัด 5 MB) ต้องตัดสินใจว่าใช้ IndexedDB หรือย่อรูปแรง ๆ (คำถาม Q5)
5. **ความเสี่ยงที่ 2:** เทสต์ที่มีอยู่ (~800 ตัว, 12 ไฟล์ `App.*.test.tsx`) ผูกกับสคีมา v2 และข้อความหน้าจอ — เปลี่ยนสคีมาแล้วต้องเขียนตัวอย่างข้อมูลกลาง (`fixtures`) ใหม่ก่อน ไม่งั้นทุก PR จะแดงยกชุด
6. **ความเสี่ยงที่ 3: ผืนงานยังไม่ครบสเปก** — ไม่มีบอร์ดสำหรับ แพ้ยา, สิทธิ์รักษา, สรุปให้หมอ (ข้อความล้วน), ตั้งค่าย่อย 3 ใน 5 หมวด, ขนาดตัวอักษร; ฟอร์มสมาชิกมี "ญาติ" แต่โค้ดมี "อื่น ๆ"; ประกันในฟอร์มเป็นช่องชื่อบริษัท 2 ช่อง ไม่ใช่ "ประเภท+บริษัท" → ต้องถามเจ้าของ (หัวข้อ 6) ห้ามเดา
7. ปุ่มที่ในผืนงานเป็น `href="#"` (กดแล้วไม่เกิดอะไร) มีหลายจุด เช่น ลิงก์ในหน้าสมาชิกรายคน, 4 หมวดในตั้งค่า — ต้องไม่เอามาเป็นปุ่มจริงในแอพ (ตรงกับข้อ 17)
8. เกณฑ์ "ใกล้หมด" ในผืนงานตั้งต้น 14 วัน แต่โค้ด/Q5 คือ 7 วัน → ต้องถาม (Q3)
9. ลำดับ PR ที่เสนอ: **15 รายการ** (หัวข้อ 5) เจ้าของเริ่มลองใช้จริงได้หลัง PR ที่ 7 (รายการยา + เพิ่มยา + รายละเอียดยา)
10. ไม่ต้อง migration (เจ้าของล้างข้อมูลได้) → เสนอคีย์ `judya.v3`; จุดที่ต้องระวังคือ `judya.v2` เก่าต้องไม่ถูกแตะ/ลบ (กฎใน CLAUDE.md ยังใช้ต้องแก้ข้อความเป็น `judya.v3`)

## 4. สคีมา v3 ที่เสนอ (เฉพาะส่วนที่ต่างจาก v2 — ไม่มีโค้ด)

คีย์เก็บ `judya.v3`, ไฟล์สำรอง `version: 3`, สำรองก่อนกู้คืน `judya.v3.prev`. ไม่มี migration; `judya.v2` เดิมไม่แตะ

**Medication (ต่อ "ยา 1 ชื่อ")**
- เพิ่ม `kind`: `tablet | capsule | liquid | cream | sachet | drops | other` (7 ค่า; `drops` = หยอด/สเปรย์)
- เพิ่ม `strength?`: `{ value: number, unit: 'mg' | 'mcg' | 'g' | '%' | 'IU' | 'mg/5 ml' }` (ชื่อยาไม่ต้องรวมความแรงอีก)
- เพิ่ม `pack`: union ตามบรรทัด "ซื้อมาเป็น" — `none` | `strip {perStrip}` | `box {strips, perStrip}` | `container {amount, unit: 'ml'|'g'}` | `sachetBox {sachets}`
- `unit` เดิมให้ derive จาก `kind` (เม็ด/แคปซูล/มล./หลอด/ซอง) หรือคงไว้เป็นข้อความแสดงผล
- เพิ่ม `sideEffects?: string` (ข้อความอิสระต่อยา — ตามสเปก "ต่อยา" วางที่ Medication หรือ Assignment ต้องถามเจ้าของ Q6)

**Assignment (ยาของสมาชิก 1 คน)**
- `stock` เป็น union: `{ kind:'count', strips:number, loose:number, countedOn }` | `{ kind:'volume', ml:number, countedOn }` | `{ kind:'tubes', opened:boolean, spare:number }` (ครีม/หยอด ไม่หักอัตโนมัติ; ปุ่ม "เปิดหลอดใหม่" ลด `spare` +1 เปิด)
- ตัด `note` ที่เป็นของการแก้ไขออกจากประวัติ (เก็บเป็น field ธรรมดาได้)

**MedEvent**
- `type`: `start | adjust | stop | resume` (**ตัด `edit`**)
- `adjust`: `reason: 'doctor' | 'self_or_other'` + `note` + `from/to` schedule; `stop`: reason ตามรายการที่เจ้าของยืนยัน (Q8) + note
- `Snapshot` เหลือแค่ `schedule`

**Person**
- `birthYearBE` คงไว้ (ห้ามเก็บวันเต็ม — มีอยู่แล้ว)
- เพิ่ม `avatar: AvatarName` (12 ตัวเลือกจากรูปที่มีอยู่แล้ว) — ตัด `avatarForIndex`
- เพิ่ม `allergies`: `{ status: 'unknown' } | { status: 'none_confirmed', confirmedAt } | { status: 'listed', items: { drug: string, reaction: string }[] }`
- แทน `insurance` ด้วย `coverage?: { type: 'government' | 'social' | 'civil_servant' | 'private' | …(รายการจริงรอเจ้าของ Q7), company?: string /* เฉพาะ private */ }` ห้ามมีฟิลด์เลขกรมธรรม์/เลขบัตร (ให้ zod `.strict()`)
- `relation` ให้ตรงกับที่เจ้าของเลือก (ผืนงาน: แม่ พ่อ ลูก คู่สมรส ญาติ อื่นๆ; โค้ด: ตัวฉัน พ่อ แม่ คู่สมรส ลูก อื่น ๆ) Q4

**Price**
- เพิ่ม `date: isoDate`, `receipt?: { id }` (อ้างอิงรูป — ที่เก็บรูปรอ Q5), คงหน่วยขาย/ราคา/`perSellUnit`

**Order (ใหม่ทั้งตาราง `orders: Order[]`)**
- `Order { id, shopId, createdAt, status: 'waiting' | 'partial' | 'received' | 'cancelled', includeShipping: boolean, lines: OrderLine[], note? }`
- `OrderLine { source: { kind:'assignment', medicationId } | { kind:'house', houseItemId } | { kind:'free', name }, qtyOrdered, sellUnit, perSellUnit?, unitPrice?, qtyReceived, leftover: 'waiting' | 'dropped' | null, addToList?: boolean }`
- การรับของเขียนสต็อกเฉพาะบรรทัดที่ `source.kind !== 'free'`

**Settings**
- ตัด `orderTemplate` ไม่ได้ (ยังใช้) · เพิ่มค่าที่หมวดตั้งค่าใหม่ต้องใช้ตามคำตอบ Q9 (เช่น ตั้งค่าส่ง/ร้านโปรด) · `lowStockDays` ค่าเริ่มต้นรอ Q3 (7 หรือ 14)

**Root / meta**
- `version: 3`; `meta.lastBackupAt` คงไว้; `prepLog` คงไว้ (ถ้ายังมีการจัดยาวันนี้ — Q2)
- ไฟล์รูปใบเสร็จ: ถ้าเลือก IndexedDB ต้องนิยาม `receipts` ในไฟล์สำรองและขีดจำกัดขนาด (Q5)
