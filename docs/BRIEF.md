## 2. โมเดลข้อมูลใหม่ (รุ่นข้อมูล 2)

เก็บเป็น JSON ก้อนเดียว คีย์ `judya.v2` (ห้ามแตะ `judya.v1` และ `medmate.v1` ที่อยู่โดเมนเดียวกัน)
วันที่เป็น `YYYY-MM-DD` ตามเวลาไทย, เวลาเป็น ISO มี offset, id สุ่มสั้น, ตรวจด้วย zod ทุกครั้งที่โหลด/นำเข้า

```ts
interface Root {
  version: 2;
  persons: Person[]; medications: Medication[]; assignments: Assignment[];
  events: MedEvent[];            // ประวัติยา เพิ่มได้อย่างเดียว ห้ามแก้/ลบ
  houseItems: HouseItem[]; shops: Shop[]; prices: Price[];
  settings: Settings; prepLog: Record<string /*date*/, Record<string /*doseKey*/, true>>;
  meta: { createdAt: string; lastBackupAt?: string };
}

interface Person { id; name /*1–40*/; relation: 'ตัวฉัน'|'พ่อ'|'แม่'|'คู่สมรส'|'ลูก'|'อื่น ๆ';
  birthYearBE?: number; color: 'blue'|'green'|'yellow'|'gray';
  selfManaged: boolean;          // จัดยาทานเอง: ไม่ขึ้นยาวันนี้ แต่ยังนับสต๊อกและเตือนสั่ง
  insurance: { health?: string; accident?: string };
  removedAt?: string; }          // นำออก = ซ่อน ไม่ลบ (นำกลับได้)

// ยา 1 ชื่อ+ความแรง ใช้ร่วมได้หลายคน (ราคาผูกที่นี่) — Q6: ชื่อตรงกัน (ไม่สนตัวพิมพ์/ช่องว่างหัวท้าย) ใช้ Medication เดิม
interface Medication { id; name /*2–60 ตามที่พิมพ์ เช่น "Tonizep FDT 5 mg"*/; unit: string /*เม็ด แคปซูล ซอง มล. ...*/;
  suggestionId?: string; }

// ยาของสมาชิก 1 คน
interface Assignment { id; medicationId; personId;
  schedule: MealSchedule | IntervalSchedule;
  stock: { qty: number /*0–9999 ทีละ 0.5*/; countedOn: string } | null;   // Q2: จำนวน ณ เช้าวันที่นับ แอพหักตามวิธีกินเอง
  expiry?: string; note?: string;
  status: 'active'|'stopped'; createdAt: string; }

interface MealSchedule { kind: 'meal';
  slots: Partial<Record<'morning'|'noon'|'evening', { pills: number; meal: 'before'|'with'|'after' }>
               & { bedtime: { pills: number } }>;     // pills 0.5–4 ทีละ 0.5
  days: { kind: 'daily' } | { kind: 'alt'; anchor: string } | { kind: 'weekdays'; days: number[] /*0=อาทิตย์*/ }; }
interface IntervalSchedule { kind: 'interval'; everyHours: 4|6|8|12|24; firstTime: string /*HH:MM*/; pills: number;
  course: { kind: 'days'; days: number /*1–90*/; startDate: string } | { kind: 'ongoing' }; }

interface MedEvent { id; assignmentId; type: 'start'|'adjust'|'stop'|'resume'|'edit';
  effectiveOn: string; at: string;
  from?: Snapshot; to?: Snapshot;          // adjust/edit เก็บค่าก่อน-หลัง
  reason?: 'หมอสั่ง'|'แพ้ยา'|'ใช้ยาไม่ได้ / ผลข้างเคียง'|'อื่น ๆ';   // บังคับสำหรับ adjust และ stop
  note?: string /*≤200*/; }

interface HouseItem { id; name /*2–60*/;
  stock?: { qty: number; unit: string /*เม็ด แคปซูล ขวด หลอด ซอง แผง กล่อง หรือพิมพ์เอง*/ };   // ไม่มี = ไม่นับสต๊อก ไม่เตือนซื้อ
  lowAt?: number;                // เตือนเมื่อเหลือ ≤ ค่านี้ (ต้องมี stock)
  expiry?: string; note?: string; removedAt?: string; }

interface Shop { id; name /*2–40*/; phone?: string /*ตัวเลข ช่องว่าง - + 6–20 ตัว*/;
  delivery: { kind: 'pickup' } | { kind: 'deliver'; fee: number /*0 = ส่งฟรี*/; freeOver?: number }; }

interface Price { id; shopId;
  item: { kind: 'med'; medicationId } | { kind: 'house'; houseItemId };
  price: number /*บาท > 0*/; sellUnit: string /*กล่อง แผง ขวด ซอง หลอด กระปุก หรือพิมพ์เอง*/;
  perSellUnit: number; }          // ยาประจำตัว = กี่ {unit} ต่อ 1 หน่วยขาย; ยาสามัญ = 1 เสมอ

interface Settings { expiryWarnDays: number /*1–365 ค่าเริ่มต้น 15*/;
  lowStockDays: number /*1–60 ค่าเริ่มต้น 7 (Q5)*/;
  orderTemplate: string /*ตัวแปร {ร้าน} {รายการ}*/;
  orderDays: number /*7–90 ค่าเริ่มต้น 30 (Q4)*/; }
```

กฎสำคัญ
- ลบร้าน → ลบราคาของร้านนั้นทั้งหมด (ตามผืนงาน) มีกล่องยืนยัน
- หยุดยา: เก็บประวัติครบ, ไม่ขึ้นยาวันนี้, ไม่เตือนสั่ง, ย้ายไป "ยาที่หยุดแล้ว"
- นำสมาชิกออก: ยาของคนนั้นซ่อนทั้งหมด (ไม่เตือน ไม่สั่ง) นำกลับได้
- ข้อความ LINE ห้ามมีชื่อสมาชิก
- บล็อกแพ้ยาเมื่อไม่มีบันทึก แสดง "ยังไม่พบการแพ้ยา" ห้ามเขียน "ไม่แพ้ยา"
- ไม่ใส่วันหมดอายุ = แสดง "ไม่ระบุ" ไม่เตือน
- ผืนงานนับวันในสัปดาห์เริ่มที่ จันทร์ = 0 แต่โมเดลใช้ อาทิตย์ = 0 (แบบ `calc.mjs`) ต้องแปลงที่หน้าจอ และมีเทสต์

### ช่องว่างที่ผืนงานยังไม่ได้ออกแบบ (ต้องตัดสินก่อนลงมือ)
1. **เพิ่มยาไม่มีขั้นใส่จำนวนที่มี/หน่วย/วันหมดอายุ** ผืนงานให้แก้ทีหลังใน "แก้ไขข้อมูลยา" เท่านั้น → Q3
2. **สต๊อกลดลงเมื่อไร** ผืนงานไม่ได้กำหนด และโค้ดเดิมก็มีจุดบกพร่องนี้ (เก็บจำนวนแต่ไม่เก็บวันที่นับ วันเหลือจึงไม่ลดลงเอง) → Q2
3. **สั่งยากี่หน่วย** ผืนงานใช้ "จำนวนกล่องของแอพ" ที่ไม่มีที่ให้ใส่ขนาดกล่อง → Q4
4. **เกณฑ์ "ใกล้หมด" ของยาประจำตัว** ผืนงานไม่มีช่องตั้ง → Q5
5. **ปุ่มเพิ่มสมาชิก** มีปุ่มแต่ไม่มีบอร์ด → ใช้ฟอร์มแก้ไขแบบว่าง (Q11)

### 3.2 การเก็บข้อมูล
- **localStorage คีย์เดียว `judya.v2`** ข้อมูลทั้งบ้านน่าจะไม่ถึง 200 KB (ขีดจำกัด ~5 MB) ใช้แบบ "ตรวจ → เขียน → อ่านกลับ → ตรวจ, ถ้าพังคืนค่าเดิม" จาก `storage.ts` เดิม
- IndexedDB ไม่เลือก: ซับซ้อนกว่า (async) แต่ไม่ได้ประโยชน์ที่ขนาดข้อมูลนี้ และไม่ได้ทนกว่าเรื่องถูกลบ
- เรียก `navigator.storage.persist()` ตอนเปิดครั้งแรกและหลังบันทึกยาตัวแรก แสดงผลในตั้งค่า ("เบราว์เซอร์รับปากจะไม่ลบข้อมูล: ใช่/ไม่")
- ทุกการแก้ข้อมูลผ่านฟังก์ชันกลาง (`actions.ts`) ห้ามหน้าจอเขียน storage เอง (ผืนงานเขียน localStorage กระจาย 5 คีย์ ห้ามลอกแบบ)
- วัน "วันนี้" คำนวณด้วย `Intl` เขตเวลา Asia/Bangkok, ส่งค่า today เข้าฟังก์ชันคำนวณเสมอ (เทสต์ได้)

### 3.3 สำรองและนำกลับข้อมูล
- สำรอง: สร้างไฟล์ `judya-backup-YYYY-MM-DD.json` แล้วเปิดเมนูแชร์ของ Android (Web Share API พร้อมไฟล์) ให้เลือก Google Drive / LINE Keep / ไฟล์ ถ้าแชร์ไม่ได้ให้ดาวน์โหลด
- นำกลับ: เลือกไฟล์ → ตรวจ zod → แสดงสรุป ("สมาชิก 3 คน ยา 9 รายการ") → ยืนยัน → แทนที่ทั้งหมด (สำรองค่าปัจจุบันไว้ใน `judya.v2.prev` ก่อน)
- เตือนสำรองที่หน้าตั้งค่าเมื่อไม่ได้สำรองเกิน 14 วัน (ไม่เด้งรบกวน)

### 3.6 กฎข้อมูลสุขภาพและความเป็นส่วนตัว (ทุก session ต้องทำตาม)
- repo เป็น public: **ห้ามใส่ข้อมูลยาจริงของครอบครัว** (ชื่อยาจากใบเสร็จร้านราชวิถีเภสัช, ชื่อคุณพ่อคุณแม่, วันหมดอายุจริง) ลงโค้ด เทสต์ หรือเอกสาร ใช้ข้อมูลสมมติที่ไม่ตรงกับคนจริง
- แอพเปิดครั้งแรกเป็นบ้านว่าง มีปุ่ม "ลองดูด้วยข้อมูลตัวอย่าง" (ข้อมูลสมมติ ลบได้ทั้งชุด) (Q12)
- ไม่มี analytics, ไม่มี backend, ไม่ส่งข้อมูลออกนอกเครื่องยกเว้นผู้ใช้กดแชร์เอง
- ทุกหน้าที่เกี่ยวกับวิธีกินยาคงข้อความ "ตรวจกับฉลาก/แพทย์/เภสัชกร" ตามผืนงาน แอพไม่แนะนำขนาดยา

## 4. ตรรกะคำนวณ (โมดูล `domain/` ฟังก์ชันบริสุทธิ์ ไม่มี UI)

| ฟังก์ชัน | กฎ | ที่มา |
|---|---|---|
| `isTakeDay(schedule, date)` | daily / alt (นับจาก anchor ห้ามก่อน anchor) / weekdays / interval-course (ภายในจำนวนวันคอร์ส) | ยืม `calc.mjs` + เพิ่ม |
| `dosesOn(schedule, date)` | meal = ผลรวม pills ทุกช่วง; interval = (24/everyHours) × pills | ใหม่ |
| `stockNow(assignment, today)` | qty − ผลรวม dosesOn ทุกวันกินตั้งแต่ countedOn ถึงเมื่อวาน (วันนี้ยังไม่หัก); ไม่ต่ำกว่า 0; ไม่มี stock = unknown; ช่วงที่หยุดยาไม่หัก | ใหม่ (Q2) |
| `stockWalk` → `daysLeft` | เดินทีละวัน ห้ามใช้ค่าเฉลี่ย (ผืนงานใช้ค่าเฉลี่ย ห้ามลอก) | ยืม `calc.mjs` |
| `isLowStock` | daysLeft ≤ settings.lowStockDays | ใหม่ |
| `expiryStatus(expiry, today, warnDays)` | ไม่มีวัน = unknown; < 0 = expired; 0..warnDays = soon; อื่น ok | ยืม + เปลี่ยน 30 → ค่าจากตั้งค่า |
| `houseStatus(item)` | ไม่มี stock = ไม่นับ; qty ≤ lowAt = low; qty = 0 = "หมดแล้ว" | ใหม่ |
| `cutHouseStock(item, n)` | n ≥ 1, ห้ามติดลบ (ตัดเกินให้เตือน ไม่ตัด) | ใหม่ |
| `orderNeed(assignment, today, orderDays)` | max(targetQuantity(orderDays) − stockNow, 0) หน่วยยา; หน้าสั่งยาปรับ +/− ได้; ยาชื่อเดียวกันหลายคนรวมเป็นบรรทัดเดียว (Q6) | ยืม `targetQuantity` |
| `compareShops(lines, shops, prices, inclShip)` | เข้าเทียบเฉพาะร้านที่มีราคาครบทุกรายการที่ติ๊ก; ยาประจำตัว `ceil(need / perSellUnit)` หน่วยขาย; ยาสามัญ n × ราคา; pickup ค่าส่ง 0; deliver: ยอดยา ≥ freeOver → 0 ไม่งั้น fee; สวิตช์รวม/ไม่รวมค่าส่ง; เรียงถูกสุดก่อน (เท่ากัน เรียงตามชื่อร้าน); บอก "ซื้อเพิ่มอีก ฿x ส่งฟรี"; รายการขาดราคาพร้อมลิงก์ | ผืนงาน v35 (เขียนใหม่ ไม่ใช้ `lineCost` เดิม) |
| `buildOrderMessage(template, shopName, lines)` | แทน {ร้าน} {รายการ}; ไม่มี {รายการ} → ต่อท้าย; ไม่มีร้านครบราคา → "ร้านยา"; ไม่มีชื่อสมาชิก | ผืนงาน |
| `todayDoses(data, today, who)` | ยกเว้น selfManaged, stopped, สมาชิกที่นำออก; จัดกลุ่ม ช่วงเวลา → ก่อน/พร้อม/หลังอาหาร | ผืนงาน |
| `validate*` | ชื่อ ≥ 2 ตัวอักษร, เบอร์โทร, ปีเกิด พ.ศ. 4 หลัก (2400–ปีปัจจุบัน), ราคา > 0, ค่าส่ง ≥ 0, ยอดส่งฟรี > 0 หรือว่าง | ผืนงาน |

## 5. เกณฑ์ตรวจรับแต่ละขั้น (ต้องผ่านทุกข้อจึงไปขั้นต่อไป)

### 3.1 โครงแอพ (1–2 session)
1. เทสต์ 18 ตัวจาก `calc.test.mjs` ย้ายมาแล้วผ่านทั้งหมด (`npm test` เขียว ใน GitHub Actions)
2. type check ผ่านแบบ strict ไม่มี `any`
3. เทสต์ storage: บันทึก/โหลด/ข้อมูลเสีย/รุ่นข้อมูลไม่ตรง/พื้นที่เต็ม → ข้อมูลเดิมไม่หาย (≥ 6 เทสต์)
4. หน้าเปล่า 4 แท็บพร้อมเมนูล่าง ใช้สี/ฟอนต์/ขนาดจาก tokens (ตัวอักษร ≥ 15px, พื้นที่กด ≥ 48px)
5. Deploy สำเร็จ; **ผู้ใช้ทดสอบบน S24**: เปิด URL ได้ → "เพิ่มลงหน้าจอหลัก" ได้ → ไอคอน JudYa ขึ้น → เปิดตอนโหมดเครื่องบินได้
6. Lighthouse PWA/Accessibility ≥ 90 (ถ้ารันในคลาวด์ได้; ถ้าไม่ได้ บันทึกเป็นความเสี่ยง)

### 3.2 หน้าหลัก ยา สมาชิก (3–4 session: a ยาวันนี้+หน้าแรก · b เพิ่มยา+รายละเอียดยา · c สมาชิก · d สำรองข้อมูลถ้าอนุมัติ Q8)
1. เทสต์ใหม่ผ่าน: dosesOn, stockNow, daysLeft (ทุกวัน, วันเว้นวัน, เลือกวัน, ทุก X ชม., คอร์สจบ), expiryStatus กับเกณฑ์ 15 และ 1/365, todayDoses (ไม่รวมจัดยาเอง/หยุดยา/นำออก), events บังคับเหตุผล, แปลงวันจันทร์=0 ↔ อาทิตย์=0
2. เทสต์หน้าจอ (Testing Library) อย่างน้อย: เพิ่มยา 3 ขั้นแล้วยาขึ้นในยาวันนี้, ติ๊กจัดยาแล้วรีโหลดยังติ๊กอยู่, วันใหม่ติ๊กหาย, ปรับโดสไม่มีเหตุผลกดบันทึกไม่ได้, หยุดยาแล้วย้ายไป "ยาที่หยุดแล้ว", นำสมาชิกออก/นำกลับ
3. **ผู้ใช้ทดสอบบน S24**: เพิ่มยาจริง 1 ตัว (ใส่จำนวนที่มี) → วันยาเหลือบนหน้าจอตรงกับที่ผู้ใช้คิดมือ; ทำ 3 งานของ M2 ได้ (ดูยาวันนี้ / เพิ่มยา / รู้ว่ายาตัวไหนใกล้หมด)
4. ทุกหน้าเทียบผืนงานแล้ว: ลำดับ ข้อความ สถานะใช้ไอคอน+ข้อความ (ไม่ใช้สีอย่างเดียว)

### 3.3 สั่งยาและร้านค้า (2–3 session)
1. เทสต์เทียบราคา ≥ 15 เคส: ร้านขาดราคา, ปัดหน่วยขายขึ้น, ยาสามัญ n หน่วย, pickup, ส่งฟรีเมื่อครบ, ยอดพอดีเกณฑ์ส่งฟรี, รวม/ไม่รวมค่าส่ง, ราคาเท่ากัน, ไม่มีร้าน, ไม่ติ๊กเลย, ลบร้านแล้วราคาหาย
2. เทสต์ข้อความ: มี/ไม่มี {รายการ}, ไม่มีชื่อสมาชิก, ไม่มีร้านครบราคา
3. เทสต์ยาสามัญ: ตัดจำนวน (ห้ามติดลบ), เตือนใกล้หมด, ไม่นับสต๊อก, ลบ/นำกลับ, ยาสามัญใกล้หมดขึ้นหน้าแรกและหน้าสั่งยา 1 หน่วย ปรับ +/−
4. **ผู้ใช้ทดสอบบน S24**: ใส่ร้าน 2 ร้าน + ราคา → สั่งยา 3 รายการ → กดส่ง → วางใน LINE ได้ข้อความถูกต้อง; ปุ่มโทรเปิดแป้นโทรศัพท์

### 3.4 ส่งสรุปยาและสำรองข้อมูล (1–2 session)
1. ภาพสรุปสร้างในเครื่อง (ไม่ส่งข้อมูลออก) ตัวอักษรไทยถูกต้อง อ่านได้บนจอมือถือ
2. **ผู้ใช้ทดสอบบน S24**: ส่งภาพ + ข้อความสรุปยาของสมาชิก 1 คนทาง LINE ได้จริง
3. สำรอง → ล้างข้อมูลเว็บใน Chrome → นำกลับ → ข้อมูลครบเท่าเดิม (ผู้ใช้ทำตามขั้นที่ทีมเขียนให้)

### 3.5 ใช้จริง 7 วัน
ผู้ใช้จดปัญหาลงแชท; ผ่านเมื่อไม่มีบั๊กที่ทำให้ตัวเลขยา (วันเหลือ จำนวน ราคา) ผิด และไม่มีข้อมูลหาย

## ภาคผนวก A — ข้อความเริ่มงานขั้น 3.1 (วางใน Claude Code, Sonnet 5.5)

```
คุณคือทีมพัฒนาแอพ JudYa (PWA จัดการยาในบ้าน ภาษาไทย) เจ้าของไม่ใช่โปรแกรมเมอร์ ตอบเป็นภาษาไทยง่าย ๆ
อ่าน docs/BRIEF.md ทั้งไฟล์ก่อนเริ่ม ทำเฉพาะขั้น 3.1 ห้ามทำหน้าจอของขั้นถัดไป
งาน:
1. ตั้งโครง Vite + React + TypeScript strict + Vitest + zod + vite-plugin-pwa ใน root ของ repo
2. คัดลอก reference/calc.mjs และ calc.test.mjs จาก repo MonPlayPark/JudYa (อ่านอย่างเดียว) แปลงเป็น TypeScript ที่ src/domain/calc.ts ให้เทสต์ 18 ตัวผ่าน ระบุที่มาใน commit
3. ทำ src/domain/schema.ts (zod) และ storage.ts คีย์ judya.v2 ตามหัวข้อ 2 และ 3.2 ของ BRIEF พร้อมเทสต์ ≥ 6 ตัว ห้ามอ่านหรือแก้คีย์อื่นใน localStorage
4. ธีมจาก tokens (หัวข้อ 3.1 ของ BRIEF), ฟอนต์ @fontsource/noto-sans-thai, hash router, หน้าเปล่า 4 แท็บ + เมนูล่าง
5. manifest + service worker (ออฟไลน์), workflow GitHub Actions: test → build → deploy Pages เฉพาะ main
6. CLAUDE.md สั้น ๆ, docs/HANDOFF.md, docs/DECISIONS.md
กฎ: ทำบน branch เปิด PR ห้าม merge เอง, ห้ามใส่ข้อมูลยาหรือชื่อคนจริง, commit ทีละเรื่อง ข้อความ commit ภาษาอังกฤษ
จบ session: รัน npm test และ npm run build ให้ผ่าน, อัปเดต docs/HANDOFF.md, สรุปให้เจ้าของว่าต้องทดสอบอะไรบน S24 ตามเกณฑ์ 3.1 ข้อ 5
ถ้าเจอสิ่งที่ BRIEF ไม่ได้ระบุ ให้หยุดถาม ห้ามเดา
```
(ข้อความเริ่มงาน 3.2–3.4 จะเขียนตอนจบแต่ละขั้น เพื่อใส่สิ่งที่เรียนรู้จากขั้นก่อน)

## ภาคผนวก B — สร้าง repo ใหม่บนมือถือ (ผู้ใช้ทำ 1 ครั้ง ก่อนขั้น 3.1)
1. เปิดแอพ GitHub → แตะรูปโปรไฟล์ (ขวาล่าง) → ถ้าใช้บัญชีองค์กร MonPlayPark ให้สลับไปหน้า MonPlayPark ก่อน
   (ถ้าในแอพไม่มีปุ่มสร้าง repo ให้ใช้ Chrome → github.com/new)
2. ช่อง Owner เลือก **MonPlayPark** · Repository name: **judya-app**
3. เลือก **Public** (GitHub Pages ฟรีใช้กับ repo public)
4. ติ๊ก **Add a README file** (เพื่อให้ Claude Code เปิด repo ได้ทันที) · .gitignore และ license ไม่ต้องเลือก
5. กด **Create repository**
6. ตั้ง Pages ต่อทันทีตามขั้นในหัวข้อ 3.5 (ถ้าไม่ตั้งก่อน การ deploy ครั้งแรกจะล้ม)
7. แจ้งทีมในแชทว่า "สร้าง repo และตั้ง Pages แล้ว"
